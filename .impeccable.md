# Drip — Design Context

## Design Context

### Users
Single user: a developer/consultant (Marek) using this as a personal daily driver for time tracking, deep work, and end-of-day logging. Used throughout the workday — opening it dozens of times. The context is heads-down, often mid-task. The tool must never feel like an interruption or demand attention.

### Brand Personality
**Sharp. Personal. Unobtrusive.**

Feels handcrafted for one person — not generic productivity software. Precise and fast like a command-line tool; polished and high-density like a developer tool. Every element earns its place.

Emotional goal: when you open Drip, you feel in control — not overwhelmed, not infantilized. It trusts you to know what you're doing. Working in it should feel satisfying, like a well-balanced tool.

### Aesthetic Direction
**Primary reference: Raycast** — minimal, command-palette feel, near-zero decoration, fast and keyboard-friendly. Information appears exactly when needed and disappears when not.

**Secondary reference: Linear** — polished dark UI, refined typography, high information density, subtle depth through elevation rather than heavy borders.

**Anti-references**: Generic productivity apps (Notion-style airyness, rounded colorful icons, lots of empty space). Gamified apps. Anything that feels like it's trying to motivate you with cheerful UX.

**Theme**: Dark-only. Very dark base (`#0a0a0c`). Amber/orange (`#f59e0b`) as the sole accent — the personality of the app. Everything else recedes into the dark. Emerald green only for break state. No other accent colors except semantic (red for errors, blue for calendar).

**Typography**: Outfit for display/UI labels. JetBrains Mono for the timer countdown, task IDs, numbers, and any data that benefits from monospace alignment.

### Design Principles

1. **Recede when idle, shine when active.** At rest, the interface is near-invisible — dark, low-contrast, quiet. When in focus mode, the orange accent pulses forward. The timer is the loudest thing on screen when running; everything else dims.

2. **Density over whitespace.** Prefer compact layouts with clear visual hierarchy over spacious, airy ones. More information visible at once = fewer context switches. Use spacing purposefully, not decoratively.

3. **One accent, used with precision.** Orange (`focus`) is the entire personality of the app. Use it to direct attention — active states, current item, primary action. Avoid diluting it with secondary accent colors or decorative use.

4. **Borders as structure, not decoration.** Borders communicate containment and separation. Use `border-focus/20` for subtle structure, `border-focus/30` for prominent containers. Never use solid fills where a transparent background + border does the job.

5. **Interactions feel mechanical, not playful.** Transitions should be fast (`150–200ms`), not bouncy. Hover states are subtle (`bg-focus/5`). Animations (glow-breathe, fade-in) are reserved for the timer state — not scattered through the UI. The tool respects that you're in the middle of something.
